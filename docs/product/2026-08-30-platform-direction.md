# Gensokyo 平台内容方向与首发模块产品文档

2026-08-30 · 状态：已批准

## 定位

**东方众的资源与数据基础设施**，单站多模块，**面向全球而非仅国内**：UI 首发三语 **zh / ja / en**（zh 为基准，URL 无前缀；`/ja/*`、`/en/*` 带前缀），用户与协作开发者增长后拓展更多语言。ja 支持有战略意义——东方社团几乎都在日本，日语界面是"社团认领/下架通道"真正可用的前提。用户内容（资源标题、社团名等）采用多语字段设计，从第一张业务表开始落实。长期覆盖全部可行方向（百科 / 结构化数据 / 资源分发 / 创作发布 / 补丁本地化 / 玩家工具 / 流媒体电台 / 社区论坛 / 活动展会 / 仪式性数据活动 / 导航门户——档案保存因法律灰色明确不做），AI 时代不惧时间成本：先做出所有可用的，日后慢慢养用户。

## 生态判断（2026-08 调研）

- **THBWiki**：内容霸主但 TBSGroup 已停摆，靠静态备用站维持。不正面做百科；其非结构化、无 API 是缺口。
- **inarigal**（中文 UGC 资源社区）：已 502 瘫痪。**资源分发位是空的，且刚空出来**。
- **TouhouDB**（VocaDB 分支）：已用开放 API 占住东方音乐结构化数据（英文侧）。chronicle 不从零建库，**做 TouhouDB API 之上的中文层**（中文译名/拼音搜索/中文社团补全/与 THBWiki 互引）。
- **Gensokyo Radio**：英文侧 24/7 电台。中文侧流媒体/点播空缺。
- 社区：贴吧衰落、QQ 群孤岛。论坛冷启动最难，靠资源站供血。

三条被验证的成长路径：工具→社区（op.gg）、数据→应用生态（MusicBrainz/vndb）、资源→社区（NexusMods）。本平台走**资源→社区**为主线，数据层并行。

## 两条生死线

1. **版权分级**：ZUN 二创指引友好，但社团普遍禁止全曲/整本再分发。落地为产品机制：资源必须标注**分发许可状态**（社团明示允许 / 未标明 / 已绝版 / 授权转载）；社团/作者可**认领作品页并申请下架**；官方作品本体绝对不碰。
2. **低运营成本架构**：TBSGroup 式大组织会解散。solo + AI 前提下刻意选低人肉运营的方向与机制（先发后审自动化、信任梯度、结构化数据同步）。

## 首发模块一：香霖堂 /kourindou（资源分发）

**内容类型**：同人游戏 · 同人志/图集 · 音乐专辑文件 · 汉化补丁/字幕 · 工具/素材。
**边界**：音乐专辑的文件分发归香霖堂；music 模块只做"听"（点播/歌单/聚合），不重复造分发。

**对象模型**（thdl 十二张表为地基，扩展）：

```
resource   标题/简介/类型/原作关联/展会/状态(待审|已发布|已下架)
 ├ version  版本号/更新日志——资源可更新，下载指向版本
 │  └ file  B2 对象 + 外链镜像混合；预签名直传上传，签名 URL 下载
 ├ circle   社团/作者归属（先本地表，日后与 chronicle 互通）
 ├ license  分发许可状态（生死线字段）
 ├ tag      类型 × 原作 × 展会 多维
 └ 互动     评分 / 收藏 / 感谢 / 举报 / 下载统计
```

**机制**：先发后审 + 信任梯度（新账号首个资源人工审核，通过 N 个后即发即审）；Turnstile 反机器人；认领与下架通道；Meilisearch 中文+拼音搜索。

**页面**：列表(多维筛选) / 详情(版本历史+文件+评论) / 上传向导 / 社团页 / 审核队列(管理) / 举报处理(管理)。

## 首发模块二：博丽神社 /shrine（社区论坛）

**形态**：版块式（NGA/贴吧心智），版块 → 主题帖 → 楼层回复。Markdown + 图片 + 东方表情 + @提及 + 引用。

**初始六版块**：幻想乡茶话会（综合）· 弹幕研究所（原作 STG）· 二创工坊 · 音乐堂 · 河童重工（技术）· 站务。

**结构性整合（已批准的关键设计）**：**每个资源自动挂一个讨论主题，资源评论区与论坛帖是同一份数据**（一套内容系统，两个视图）。论坛冷启动吃资源站流量；评论/通知/审核只维护一套。

**配套（两模块共用）**：统一账号（better-auth）+ 个人主页（帖子+资源+收藏聚合）；通知中心（回复/@/订阅/审核结果）；角色权限 user/版主/管理员；举报-处理-申诉闭环；信任等级两模块共享。
